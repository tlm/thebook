# Markdown Writing

This guidance applies when writing or modifying Markdown. Follow any
applicable document-specific structure and conventions as well.

## Formatting

- Keep source lines under 80 characters. Leave content that cannot
  reasonably be split, such as links, intact. Prefer placing long links on
  their own lines where possible.
- Wrap prose at word boundaries without changing rendered paragraphs.
  Separate paragraphs with a blank line.
- Use descriptive headings in a logical hierarchy, beginning with one
  document title. Do not skip heading levels merely for visual styling.
- Use fenced code blocks for multiline examples and specify the language
  when known. Preserve valid syntax and meaningful whitespace in examples;
  do not break commands, code, or URLs merely to satisfy prose wrapping.
- Use backticks for paths, commands, and code identifiers in prose.
- Use descriptive Markdown link text. Resolve relative links from the file
  containing them, and check that local destinations and heading anchors
  exist. Distinguish links to reusable guidance from links to work-item
  records or generated artefacts.
- Use lists for parallel items or ordered actions. Use tables for concise
  comparisons, not paragraph-length content forced into cells. Do not
  distort a valid table merely to satisfy the line-length limit.
- Keep project documentation short and professional. Do not use emoji.

## Existing Documents

- Preserve applicable document-specific conventions, including specialised
  heading or spacing rules. Do not reformat unrelated content.
- When changing headings or moving files, check references and update
  affected links. Avoid changing established anchors without a reason.
- Before finishing, check Markdown structure, examples, links, and source
  formatting. Use the project's existing validation tools when available.
