# Preface

This file defines how to read and maintain contributor knowledge in this
repository. References to `.kb/agents.md` mean this file at the repository
root, including when they appear in nested knowledge-base documents.

IMPORTANT: Read the `.kb/agents.md` file.


# Laws

## §1 - Scope and Organisation

Keep maintained contributor knowledge in `.kb/` directories near its
subject. These conventions apply to knowledge-base documents, not to
consumer harness artefacts or documents generated by consumers.

Use dashed lowercase Markdown filenames that are unique among knowledge
base documents in the repository.

## §2 - Headers and References

Use only these top-level headings, in this order:

- **Preface:** required; explain the document's scope and relevance. End
  with: "IMPORTANT: Read the `.kb/agents.md` file."
- **Laws:** optional; terse constraints in `## §<N> - <Title>` subsections.
- **Concepts:** optional; explanations, design details, and references.

Omit empty or trivial optional sections. Leave two empty lines before
top-level headings and one before subheadings.

Keep law numbers stable. Never change a law's subject; if obsolete, retain
its number with the heading `## §<N> - Revoked`.

## §3 - Maintenance

Record current, durable understanding rather than task logs, plans, or
conversation transcripts. Update relevant knowledge when it changes.
Link to authoritative harness instructions and standards instead of
duplicating them.

Read the root `AGENTS.md` knowledge index and load entries relevant to the
work. Maintain that index when adding, moving, or removing knowledge-base
files; include every knowledge-base document with a descriptive link.

Do not edit this convention unless explicitly requested. Report missing
guidance rather than silently assuming it does not apply.
